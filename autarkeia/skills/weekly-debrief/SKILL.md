# Weekly debrief

Before reading memory or writing, read the bundled `references/project-sessions.md` (from this skill directory: `../../references/project-sessions.md`) and resolve the vault and active project. Read the vault and parent instructions before project rules. Do not infer a vault from `memory/facts.md`; if the reference or instructions cannot be read, stop before writes. For reading and listing, unqualified paths below belong to the active scope. For every write or move, first choose the item’s owner, then resolve the path under that owner; clearly personal items use the vault, project items use their actual project folder. Explicit vault-level paths always use the resolved vault. Never append a vault-relative project path to the opened project. Privacy rules still apply.

Step back and see the week.

**Mode: mixed.** Rebuilding the work picture is act. Promoting memory and changing priorities is ask first.

Confirm the active scope from its instructions. A project review covers its week, not the entire vault. Run `date "+%Y-%m-%d"`.

## 1. Picture of the week

Run **realign** for real — rebuilding the open-work picture is exactly what you want before a weekly look. Run **health-check** dry: report only, no fixes. Then read the last seven daily logs, `memory/tasks.md`, and `PRIORITIES.md` if it exists.

## 2. Propose promotions

From the week's logs, list anything that should become a lasting fact or decision, and any task that is done or stale. Show the list. Wait.

## 3. Priorities

If `PRIORITIES.md` exists, say in one paragraph whether the week's files match it. Do not rewrite priorities unless they ask.

## 4. Questions

Ask one at a time, at most three:

- What from this week should still be true next month?
- What did you avoid?
- What is the one thing next week is for?

## 5. Write

Approved promotions go through **distill** routing. Before those writes, distill decides the owner and reads that project's rules. A private item does not get a vault line the project's rules forbid; if even a pointer is forbidden, today's log gets nothing that identifies the project, and the closing summary does not name it. Add `### Weekly debrief` to each approved item's owning daily log, including private items inside their project; do not duplicate project content in an ancestor log.

Close in three beats: what the week was, what it means, what you need from them (one thing, or nothing).
